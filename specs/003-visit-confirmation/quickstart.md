# Quickstart: проверка этапа 2 на тестовом стенде

## 0. Подготовка

1. В расширение `TGBotAPI` тестовой УМЦ: модуль из `onec/http-service.bsl`, URL-шаблон `/confirm`
   (метод POST, обработчик `ConfirmPOST`), F7.
2. Перезапустить тестового бота (схема БД мигрирует v1 → v2 сама).
3. Отправить напоминание сразу: `curl.exe -X POST -u <ADMIN_USERNAME>:<ADMIN_PASSWORD>
   "http://localhost:8001/admin/send-reminder?appointment_id=<UUID заявки>&kind=24h"`
   (UUID — в журнале бота, строка «Записан: … appointment_id=…»).

## 1. Подтверждение (US1)

Нажать «✅ Подтверждаю» → «Спасибо!», кнопки исчезли; в заявке 1С строка «Пациент подтвердил
запись (Telegram), …». Нажать ещё раз в другом напоминании → «уже подтверждён», вторая строка
не появилась. Остановить 1С-публикацию (или неверный `ONEC_URL`) → «не удалось…», кнопки остались.

## 2. Отмена (US2)

Новое напоминание → «❌ Отменить» → заявка отменена в 1С, кнопки исчезли, напоминание за 2 ч не пришло.
Кнопка в старом напоминании после отмены → «Запись уже отменена».

## 3. Чужая кнопка (US3)

Получить напоминание, перенести запись, нажать кнопку старого сообщения → «изменена», в 1С без изменений.

## 4. Напоминание за 2 часа

Подтверждённому — только «Отменить»; неподтверждённому — обе кнопки.

## 5. MAX

Контрактные тесты (`pytest`) — модерация не пропускает тестового MAX-бота; вживую — после выкладки.
