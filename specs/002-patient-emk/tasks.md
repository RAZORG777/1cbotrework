# Tasks: Пациент и ЭМК в 1С при записи через бота

**Input**: `specs/002-patient-emk/` — plan.md, spec.md, research.md (R1–R10), data-model.md,
contracts/onec-book.md, quickstart.md

**Tests**: обязательны для ботов (принцип V конституции): юнит-тесты нормализации и контрактные
тесты клиента 1С и WebApp API. Код 1С проверяется ручными сценариями quickstart на тестовой УМЦ
(автотестов 1С в проекте нет).

**Organization**: по пользовательским историям spec.md (US1–US4).

## Format: `[ID] [P?] [Story] Description`

- **[P]**: можно делать параллельно (разные файлы, нет зависимостей от незавершённых задач)
- **[Story]**: история из spec.md

- 1С: `onec/http-service.bsl` (модуль расширения `TGBotAPI`), `onec/TGBotAPI.cfe`,

## Implementation Strategy

1. **MVP**: Setup → Foundational → US1 → проверка quickstart › 1 → можно выкладывать: новые
   пациенты из бота получают медкарту.
2. **US2** сразу следом (тот же P1): без него повторные пациенты ещё будут дублироваться.
3. **US3**: коды ошибок и перенос; **US4** — в любой момент, отдельным `.cfe`.
4. Каждая история заканчивается сборкой `.cfe` и сценарием quickstart на тестовой УМЦ; выкладка на
   прод — одна, после T040 (или MVP отдельно, если регистратуре нужно раньше).
