# Data Model: Пациент и ЭМК в 1С при записи через бота

Хранилище — база 1С УМЦ. Схема базы ботов (SQLite) не меняется.

## Пациент — `Справочник.Клиенты`

| Поле | Источник | Правило |
|------|----------|---------|
| `Фамилия`, `Имя`, `Отчество`, `Наименование` | бот | новый клиент пишется штатно → `КонтрольКорректностиФИО` нормализует ФИО |
| `ДатаРождения` | бот, `YYYY-MM-DD` (принимается и `ДД.ММ.ГГГГ`) | обязательна; пустая, `0001-01-01`, в будущем или раньше 1900 → `BAD_BIRTH_DATE` |
| `Пол` | по окончанию отчества («ич» — мужской, «на» — женский) | иначе не заполняется; регистратура уточнит |
| `ОсновнаяМедицинскаяКарта` | штатно, `СоздатьМедкартуКлиента` | MUST быть заполнена после `book`/`reschedule`; иначе — пометка в заявке |
| `Автор`, `ДатаСоздания` | штатный `ПередЗаписью` | автор — пользователь `api_bot` |
| `Комментарий` | — | больше не используется для телефона; у старых клиентов бота может содержать «Тел: …» (учитывается при поиске) |

**Ключ поиска**: `ДатаРождения` (точно) + ключ ФИО = `НРег(КонтрольКорректностиФИО(ФИО))`,
«ё»→«е», пробелы схлопнуты. Помеченные на удаление не участвуют.

**Выбор среди совпавших** (FR-001, FR-005):

1. ровно один с совпадающим телефоном → он;
2. иначе ровно один по ФИО и дате → он (телефон отличается → FR-004);
3. иначе несколько → с `ОсновнаяМедицинскаяКарта`, затем самый ранний по `ДатаСоздания`;
   примечание заявки: «Проверить пациента: найдено N совпадений».

## Телефон — `РегистрСведений.КонтактнаяИнформация`

| Измерение/ресурс | Значение |
|------------------|----------|
| `Объект` | клиент |
| `Тип` | `Перечисления.ТипыКонтактнойИнформации.Телефон` |
| `Вид` | `Справочники.ВидыКонтактнойИнформации.ТелефонСотовый` |
| `Поле3`, `Представление` | `+7XXXXXXXXXX` (в базе встречаются `7…`, `+7…`, `+7(…)…` — сравнение только по цифрам) |

Пишется только новому клиенту, через `ЗаписатьНомерТелефона`. Сравнение — по последним
10 цифрам всех телефонов клиента (и «Тел: …» из `Комментарий`).

## Медицинская карта — `Справочник.МедицинскиеКарты`

| Поле | Значение |
|------|----------|
| `Клиент` | пациент |
| `ВидКарты` | учётная политика `ОсновнойВидМедКарт` |
| `Филиал` | филиал записи (`branch`), через `ПараметрыМедкарты` |
| `НомерКарты`, `Наименование` | штатно, `ОтраслевыеДополнения.ФормированиеНомера` |
| `ДатаРегистрации` | текущая дата сеанса |

Состояние у пациента: *нет карты* → (`СоздатьМедкартуКлиента`) → *есть основная карта*.
Не задан `ОсновнойВидМедКарт` → карта не создаётся, результат `medical_card = "missing"`.

## Заявка — `Документ.Заявка`

| Поле | Правило |
|------|---------|
| `Клиент` | найденный или созданный пациент |
| `Состояние` | `BOT_Первичка` (услуга содержит «первич», по умолчанию) / `BOT_Повторка` («повтор»); не найдено → запись не создаётся, `STATE_NOT_CONFIGURED` |
| `Ответственный` | пользователь `api_bot` (признак заявки бота для `Бот_Интеграция`) |
| `Примечание` | первая строка — источник: «Запись из Telegram/MAX: +7XXXXXXXXXX» или «Перенос из Telegram/MAX: …»; далее служебные пометки: «Телефон из бота: …», «Проверить пациента: …», «Медкарту завести вручную: …» |
| длительность | запись и перенос — одинаково: по услуге, затем по врачу, иначе 15 мин |

Перенос меняет ту же заявку; `Клиент` не меняется.

## Коды ошибок `book` / `reschedule`

| `code` | Когда | HTTP | Что видит пациент (бот) |
|--------|-------|------|-------------------------|
| `SLOT_TAKEN` | время занято | 200 | «Это время уже занято, выберите другое» |
| `BAD_BIRTH_DATE` | дата не распознана, пустая, в будущем, < 1900 | 200 | «Проверьте дату рождения» |
| `BAD_PHONE` | меньше 10 цифр | 200 | «Проверьте номер телефона» |
| `BAD_REQUEST` | нет обязательного поля / неверный UUID | 200 | общая ошибка записи |
| `STATE_NOT_CONFIGURED` | нет состояния `BOT_*` | 200 | общая ошибка записи, «позвоните в клинику» |
| `NOT_FOUND` | перенос: заявка не найдена | 200 | общая ошибка записи |
| `INTERNAL` | прочее исключение | 200 | общая ошибка записи |

`error` (текст) остаётся для журнала регистрации и старых ботов; ПДн в нём нет.
