# Контракт: `POST book` и `POST reschedule` (этап 1)

Дополняет `docs/onec-contract.md` §1. Реализация — `onec/http-service.bsl` (расширение `TGBotAPI`),
клиенты — `telegram_bot/app/onec_client.py`, `max_bot/app/onec_client.py`.

## Запрос

```json
{
  "branch": "Профсоюзная",
  "doctor_id": "<UUID Справочник.Сотрудники>",
  "doctor_name": "…",
  "service_id": "<UUID Справочник.Номенклатура>",
  "service_name": "Первичный прием …",
  "date": "YYYY-MM-DD",
  "time": "HH:MM",
  "patient": {
    "last_name": "…", "first_name": "…", "middle_name": "…",
    "phone": "+7XXXXXXXXXX",
    "birth_date": "YYYY-MM-DD"
  },
  "platform": "telegram | max",
  "old_appointment_id": "<UUID> (только reschedule)"
}
```

- Боты этапа 1 шлют `phone` строго `+7XXXXXXXXXX`, `birth_date` строго `YYYY-MM-DD`.
- 1С дополнительно принимает прежние `+7 (999) 123-45-67` / `8…` и `ДД.ММ.ГГГГ` (переходный период).
- `platform` отсутствует → считается `telegram` (как раньше).

## Успешный ответ (HTTP 200)

```json
{
  "status": "success",
  "appointment_id": "<UUID заявки>",
  "patient_id": "<UUID клиента>",
  "patient": "found | created",
  "medical_card": "existing | created | missing"
}
```

- `reschedule` возвращает тот же `appointment_id` (заявка переносится, а не пересоздаётся);
  `patient` для переноса всегда `found`.
- `medical_card = "missing"` — запись создана, но медкарту завести не удалось (FR-006);
  боты пишут это в журнал как предупреждение (без ПДн).
- Старые боты читают только `status` и `appointment_id` — совместимо.

## Ответ с ошибкой (HTTP 200)

```json
{ "status": "error", "code": "SLOT_TAKEN", "error": "Извините, это время уже занято." }
```

Коды и тексты для пациента — data-model.md › «Коды ошибок». Боты:

1. есть `code` → сопоставление по таблице;
2. нет `code` (старая 1С) → прежняя эвристика: «занят» в `error` → `SLOT_TAKEN`, иначе `ONEC_ERROR`.

Ошибки проверки формата в самом боте (до 1С) — HTTP 422 от бота с тем же `code`
(`BAD_PHONE`, `BAD_BIRTH_DATE`).

## Правила поиска пациента

1. Кандидаты: `ДатаРождения = birth_date`, не помечены на удаление.
2. Совпадение ФИО по нормализованному ключу (регистр, «ё»/«е», пробелы, латинская «C»).
3. Уточнение по телефону (последние 10 цифр) → см. data-model.md › «Выбор среди совпавших».
4. Не найден → новый клиент штатно + телефон в контактную информацию + основная медкарта.
5. Найден без медкарты → медкарта создаётся.

Поиск и создание — под исключительной блокировкой `Справочник.Клиенты` в транзакции записи.

## Журнал регистрации 1С

Событие `Бот.Запись`: уровень «Предупреждение» — нет медкарты, несколько кандидатов,
нет состояния; «Ошибка» — исключения. В комментарии — UUID заявки и клиента, без ФИО и телефона.
