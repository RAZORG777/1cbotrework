# Quickstart: проверка этапа 0

Проверка проводится на тестовом стенде: тестовые боты Telegram и MAX + тестовая копия УМЦ.
Контракты — в [contracts/](./contracts/), модель — в [data-model.md](./data-model.md).

## 1. Локально: автотесты

```bash
cd telegram_bot            # затем то же для max_bot
python -m venv .venv && .venv/Scripts/activate   # Windows; Linux: source .venv/bin/activate
pip install -r requirements-dev.txt
ruff check . && ruff format --check .
pytest -q
```

Ожидается: все тесты зелёные, ни один тест не ходит в сеть (respx блокирует неподменённые запросы).

## 2. Настройки

Скопировать `.env.example` → `.env` в каталоге каждого бота и заполнить тестовыми значениями.
Проверить fail-fast: удалить `ADMIN_PASSWORD` и запустить `python -m app.main`. Процесс должен
завершиться с сообщением, в котором есть `ADMIN_PASSWORD`.

## 3. Ручные действия владельца (один раз на стенд)

1. **1С (тестовая копия УМЦ)**: добавить заголовок `X-Bot-Secret` в вызовы `cancel-visit`
   и `finish-visit` для каждого бота ([onec-signals.md](./contracts/onec-signals.md)).
2. **MAX**: в кабинете партнёра MAX привязать к тестовому боту мини-приложение
   `https://<тестовый домен>/max/`.
3. **Службы**: `deploy/install-services.ps1 -NssmPath C:\tools\nssm.exe` (один раз), затем
   `deploy/deploy.ps1`.
4. **Вебхуки**: `python scripts/register_webhook.py` в каталоге каждого бота.
5. **GitHub**: Settings → Branches → защитить `main`, включить обязательную проверку `CI`.

## 4. Сценарии приёмки (по User Stories)

| # | Сценарий | Ожидается |
|---|----------|-----------|
| US1 | Открыть форму из тестового бота → «Моя запись» | видна своя запись |
| US1 | `curl <base>/my_appointment` без заголовка, затем с `Authorization: tma <чужой/поддельный>` | 401 `OPEN_FROM_BOT` |
| US1 | Открыть URL формы в обычном браузере | экран «Откройте запись через бота» |
| US2 | Записаться → `scripts/send_onec_signal.py finish <id>` → открыть форму | можно записаться снова; через 20 мин приходит просьба об отзыве |
| US2 | Запустить очистку с `PD_RETENTION_DAYS=1` на строке с `closed_at` позавчера | строка удалена |
| US3 | `curl -X POST <base>/api/v1/internal/cancel-visit` без `X-Bot-Secret` | 401, запись не изменилась |
| US3 | Отправить тот же `cancel-visit` с секретом дважды | одно уведомление пациенту |
| US3 | POST на вебхук мессенджера без секретного заголовка | 401 |
| US4 | Отправить форму без галочки согласия | запись не уходит, подсказка у чекбокса; прямой POST без `pd_consent` → 422 |
| US4 | После всех сценариев: `findstr /R "[0-9][0-9]\.[0-9][0-9]\.[0-9][0-9][0-9][0-9] +7" logs\*.log` и просмотр `/admin` | ни ФИО, ни телефонов, ни дат рождения |
| US4 (MAX) | Напоминание за 24 ч → «Подтверждаю» | в 1С появляется отметка; кнопка перестаёт «крутиться» |
| US5 | Открыть PR с намеренно падающим тестом | CI красный, мерж заблокирован |
| US5 | `deploy/deploy.ps1` на тестовом сервере | обе службы перезапущены, `/healthz` и `/max/healthz` отвечают 200 |

## 5. Выкладка в прод

После прохождения п. 4 на тесте: повторить п. 3.1–3.4 для боевых ботов и боевой УМЦ, затем
`deploy/deploy.ps1`. Первая загрузка сделает миграцию БД v0 → v1 и резервную копию `*.db.bak-v0`.
Проверить в `/admin`, что число активных записей равно числу будущих визитов.
