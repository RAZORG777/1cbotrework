# Implementation Plan: Админка как инструмент разработчика

**Branch**: `006-admin-devtool` | **Date**: 2026-10-08 | **Spec**: [spec.md](spec.md)

## Summary

Старую HTML-панель `/admin` заменяет одностраничный интерфейс с JSON API под `/admin/api/*`.
Интерфейс — три статических файла без сборки (`app/admin_ui/`), их отдаёт сам бот под той же
Basic-авторизацией. Каждый бот получает свою копию (принцип III); различия — только в проверке
мессенджера, регистрации вебхука и шаблонах кнопок.

## Technical Context

**Language/Version**: Python 3.10+ (прод — 3.13), FastAPI, APScheduler 3, loguru, SQLAlchemy 2.
**Интерфейс**: HTML + CSS + JS (ES2020) без фреймворков и CDN. Обновление журнала — опрос
`/api/logs/tail?after=seq` раз в 2 с (надёжнее SSE через туннель Cloudflare и прокси).
**Testing**: pytest + respx (внешние запросы подменены), Playwright-скриншоты интерфейса.
**Constraints**: без новых зависимостей; ПДн и секреты не попадают в API (тест сканирует ответы).

## Constitution Check

| Принцип | Как соблюдается |
|---------|-----------------|
| I. Секреты только в `.env` | `/api/settings` маскирует секреты; тест проверяет, что значений секретов нет ни в одном ответе |
| II. 1С — источник истины | консоль 1С только читает; «закрыть локально» меняет только БД бота и подписано так в интерфейсе |
| III. Два независимых бота | модули `admin_api.py`, `admin_tools.py`, `metrics.py`, `admin_ui/` — копии в каждом боте, без общих импортов |
| ПДн (FR-017) | список записей без ФИО/телефона/даты рождения; журнал уже маскируется патчером |

## Структура (в каждом боте)

```text
app/
├── metrics.py            # счётчики активности с момента запуска, время старта
├── logging.py            # + структурированный буфер (seq, time, level, message), смена уровня
├── admin_tools.py        # проверки здоровья, вебхук, шаблоны, чтение файлов журнала
├── admin_ui/             # index.html, admin.css, admin.js
└── routes/
    ├── admin.py          # страница, /logs, /send-reminder (совместимость), статика интерфейса
    └── admin_api.py      # /admin/api/*
```

## Решения

- **Уровень журнала на лету**: у обработчиков loguru фильтр читает текущий уровень из модуля;
  смена — без пересоздания обработчиков. Сбрасывается при перезапуске.
- **Файлы журнала**: читается не больше 5 МБ с конца файла, разбор строк по формату
  `время | УРОВЕНЬ | текст`; многострочные трассировки приклеиваются к своей строке.
- **«Выполнить сейчас»**: `scheduler.modify_job(id, next_run_time=now)` — разовое задание после
  запуска удаляется само, у ночной очистки следующий запуск снова по расписанию.
- **Перезапуск**: `signal.raise_signal(SIGINT)` через 0,5 с — uvicorn штатно завершает работу,
  планировщик закрывается, NSSM поднимает службу (`AppExit Default Restart`, задержка 5 с).
- **CSRF**: POST требует `X-Admin-Request: 1`; браузер не отправит такой заголовок с чужого сайта
  без CORS, а CORS бот не разрешает.
- **Счётчики**: инкременты в местах, где уже пишется журнал (вебхук, сигналы 1С, запись, перенос,
  отмена, отправка сообщений, ошибки 1С).
