# Feature Specification: Админка как инструмент разработчика

**Feature Branch**: `006-admin-devtool`

**Created**: 2026-10-08

**Status**: Draft

**Input**: User description: "Давай теперь займёмся админкой. Нужен полноценный инструмент разработчика,
откуда можно будет управлять ботом и смотреть его логи и т. д."

**Каналы**: у каждого бота своя админка. Telegram — `/admin`, MAX — `/max/admin`. Возможности
одинаковые, код в каждом боте свой (принцип III).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Разработчик за минуту видит, жив ли бот (Priority: P1)

Разработчик открывает админку и сразу видит: сколько бот работает, отвечает ли 1С и за сколько
миллисекунд, принимает ли мессенджер вебхук (адрес, очередь, последняя ошибка), работают ли БД
и планировщик, сколько ошибок в журнале за последний час, сколько записей по статусам.

**Independent Test**: остановить тестовую 1С и открыть «Обзор». Карточка 1С красная, у неё
текст ошибки. Остальные карточки зелёные.

**Acceptance Scenarios**:

1. **Given** всё работает, **When** открыт «Обзор», **Then** все проверки зелёные, видны время
   ответа 1С, адрес вебхука и число заданий.
2. **Given** 1С недоступна, **When** открыт «Обзор», **Then** проверка 1С красная с причиной
   (таймаут, HTTP-код), остальные проверки не ждут дольше 5 секунд.
3. **Given** вебхук мессенджера указывает на старый адрес туннеля, **When** открыт «Обзор»,
   **Then** видно расхождение с `WEBAPP_URL` и есть кнопка «Перерегистрировать вебхук».

---

### User Story 2 - Разработчик читает и ищет журнал (Priority: P1)

Журнал читается прямо в админке: живой хвост (новые строки появляются сами), фильтр по уровню,
поиск по тексту, выбор файла журнала (текущий и архивные), скачивание файла. Уровень подробности
можно временно поднять до DEBUG без перезапуска.

**Independent Test**: записаться в тестовом боте при открытой вкладке «Журнал». Строки о записи
появляются без перезагрузки страницы. Поиск по `appointment_id` находит их и в файле.

**Acceptance Scenarios**:

1. **Given** открыт живой хвост, **When** бот пишет в журнал, **Then** строка появляется в течение
   3 секунд; ошибки выделены цветом.
2. **Given** выбран файл журнала и задан поиск «1С», **When** нажат поиск, **Then** показываются
   последние совпадающие строки (до 2000), с уровнем не ниже выбранного.
3. **Given** нажата «Скачать», **Then** скачивается выбранный файл журнала целиком.
4. **Given** уровень переключён на DEBUG, **When** бот перезапущен, **Then** уровень снова INFO.

---

### User Story 3 - Разработчик управляет очередью заданий (Priority: P2)

Во вкладке «Задания» — все задания планировщика: напоминания, просьбы об отзыве, ночная очистка.
У каждого — тип, запись, время запуска. Задание можно выполнить сейчас, поставить на паузу,
возобновить и удалить.

**Independent Test**: записаться на послезавтра. В «Заданиях» видны `rem24h_…` и `rem2h_…`.
«Выполнить сейчас» на `rem24h_…` присылает напоминание в тестовый бот.

**Acceptance Scenarios**:

1. **Given** задание есть, **When** нажато «Выполнить сейчас», **Then** оно выполняется в течение
   нескольких секунд; разовое задание после этого пропадает из списка.
2. **Given** задание на паузе, **Then** у него нет времени запуска и есть кнопка «Возобновить».
3. **Given** удаление задания, **Then** админка спрашивает подтверждение.

---

### User Story 4 - Разработчик разбирает конкретную запись (Priority: P2)

Во вкладке «Записи» — записи бота без ФИО, телефонов и дат рождения: номер записи 1С, id
пользователя мессенджера, статус, филиал, врач, услуга, время визита, подтверждение, напоминания
вкл/выкл, задания по записи. Фильтр по статусу и поиск по номеру записи или id пользователя.
Действия: отправить напоминание (24 ч или 2 ч) сейчас, пересоздать напоминания, закрыть запись
локально (только в боте, 1С не трогается).

**Independent Test**: найти свою тестовую запись по номеру, нажать «Напоминание за 2 ч». Сообщение
приходит в бот.

**Acceptance Scenarios**:

1. **Given** запись активна, **When** нажато «Пересоздать напоминания», **Then** задания
   пересоздаются по текущему времени визита.
2. **Given** запись «зависла» (в 1С отменена, сигнал не дошёл), **When** нажато «Закрыть локально»
   с подтверждением, **Then** статус меняется, напоминания удаляются, 1С не вызывается.

---

### User Story 5 - Разработчик проверяет 1С и тексты, не трогая пациентов (Priority: P2)

Вкладка «1С» — консоль только для чтения: ping, специальности, врачи, услуги врача, расписание
врача на дату. Видны HTTP-статус, время ответа и тело ответа. Вкладка «Сообщения» показывает все
шаблоны уведомлений на примере и отправляет выбранный шаблон себе. Получатель — только id из
`ADMIN_IDS`, пациенту отсюда написать нельзя.

**Independent Test**: запросить «Врачи» по филиалу — список врачей; отправить шаблон «Напоминание
за сутки» себе — сообщение с кнопками приходит в бот.

**Acceptance Scenarios**:

1. **Given** запрос в консоли 1С, **Then** записывающие методы (book, cancel, reschedule, confirm)
   недоступны.
2. **Given** получатель не из `ADMIN_IDS`, **When** отправка шаблона, **Then** отказ 403.

---

### User Story 6 - Разработчик обслуживает бота (Priority: P3)

Вкладка «Настройки»: все настройки из `.env`; секреты показаны только как «задан» или «не задан».
Обслуживание: перерегистрировать вебхук, запустить очистку ПДн сейчас, перезапустить бот
(служба NSSM поднимает его через 5 секунд). Каждое действие в админке пишется в журнал с именем
администратора.

**Acceptance Scenarios**:

1. **Given** открыты «Настройки», **Then** ни токен, ни пароли, ни секреты не видны ни в странице,
   ни в ответах API.
2. **Given** нажат «Перезапустить» с подтверждением, **Then** бот штатно останавливается
   (задания сохранены в БД), служба поднимает его снова.

### Edge Cases

- Журнал огромный (10 МБ) — читается только хвост файла, ответ не больше 2000 строк.
- Имя файла журнала в запросе с `..` или чужим путём — 404.
- 1С или мессенджер не отвечает — проверка завершается по таймауту 5 с, страница не зависает.
- Чужой сайт пытается отправить POST в админку из браузера, где сохранён вход — запрос отклоняется
  (нужен служебный заголовок, который чужой сайт поставить не может).
- Админка открыта по туннелю с телефона — интерфейс работает на ширине 375 px.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Админка доступна только по логину и паролю администратора (`ADMIN_USERNAME`,
  `ADMIN_PASSWORD`). Все API админки — под той же проверкой.
- **FR-002**: Изменяющие запросы требуют заголовок `X-Admin-Request: 1` (защита от CSRF).
- **FR-003**: «Обзор»: время работы, версия, Python, размер и версия схемы БД, записи по статусам,
  подтверждённые, число заданий и ближайшее, счётчики активности с момента запуска (вебхуки,
  нажатия, сигналы 1С, записи, переносы, отмены, отправленные и неотправленные сообщения, ошибки 1С),
  ошибки и предупреждения в журнале за час.
- **FR-004**: Проверки здоровья выполняются параллельно, каждая не дольше 5 с: БД, планировщик,
  1С (`ping`), мессенджер (Telegram: `getMe`, `getWebhookInfo`; MAX: `GET /me`, `GET /subscriptions`).
- **FR-005**: Журнал: живой хвост из памяти (до 1000 последних строк), чтение файлов журнала
  (последние строки с фильтром по уровню и тексту), список файлов, скачивание, временная смена
  уровня (DEBUG / INFO / WARNING) до перезапуска.
- **FR-006**: Задания: список; выполнить сейчас, пауза, возобновить, удалить.
- **FR-007**: Записи: список без ПДн с фильтром и поиском; отправить напоминание; пересоздать
  напоминания; закрыть локально (отменена / завершена).
- **FR-008**: Консоль 1С только для чтения: `ping`, `specialties`, `doctors`, `services`, `schedule`.
- **FR-009**: Сообщения: предпросмотр всех шаблонов на примере; отправка шаблона только
  получателю из `ADMIN_IDS`.
- **FR-010**: Настройки без секретов; обслуживание: вебхук, очистка ПДн, перезапуск.
- **FR-011**: Каждое изменяющее действие пишется в журнал: «Админка: <действие> (<логин>)».
- **FR-012**: ФИО, телефоны и даты рождения пациентов в админку не попадают (FR-017 этапа 0).
- **FR-013**: Интерфейс работает без интернета и без сборки (ни CDN, ни npm), тёмная и светлая тема,
  ширина от 375 px, без смайликов.
- **FR-014**: Прежние адреса работают: `GET /admin/logs` (текст), `POST /admin/send-reminder`.

### Key Entities

- **Строка журнала (в памяти)**: порядковый номер, время, уровень, текст (уже с маской ПДн).
- **Счётчики активности**: имя → число с момента запуска; при перезапуске обнуляются.

## Success Criteria *(mandatory)*

- **SC-001**: Причину «бот не отвечает» (1С, вебхук, туннель, ошибка в коде) разработчик находит
  в админке за 2 минуты, без доступа к серверу.
- **SC-002**: Новая строка журнала видна в живом хвосте не позже чем через 3 секунды.
- **SC-003**: В ответах API админки нет секретов из `.env` и ПДн пациентов (проверяется тестом).
- **SC-004**: Все проверки «Обзора» укладываются в 6 секунд при недоступной 1С.

## Assumptions

- Админка нужна одному-двум разработчикам; роли и отдельные учётные записи не нужны.
- Перезапуск из админки рассчитан на службу NSSM (`AppExit Default Restart`). При ручном запуске
  бот просто остановится.
- Счётчики активности не хранятся в БД: для истории есть журнал.
- Настройки `.env` из админки не меняются: их правят на сервере и перезапускают бота.
