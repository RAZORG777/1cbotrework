# Feature Specification: Запрет онлайн-записи

**Feature Branch**: `009-booking-ban`

**Created**: 2026-11-06

**Status**: Implemented

**Input**: User description: "К нам записывается дама через MAX, уже третий раз не выходит на связь и
не приходит на приём. У меня есть её ID — если сегодня не придёт, её нужно заблокировать."

**Каналы**: Telegram-бот и MAX-бот, у каждого свой список запретов (принцип III).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Администратор запрещает онлайн-запись (Priority: P1)

Во вкладке «Записи» админки администратор вводит ID пользователя мессенджера и причину и нажимает
«Запретить запись». ID можно подставить кнопкой «Запретить запись» в строке записи.

**Acceptance Scenarios**:

1. **Given** пользователь под запретом, **When** он открывает форму, **Then** вместо выбора филиала
   видит «Онлайн-запись недоступна» и кнопку звонка в колл-центр 8 (800) 301-01-67.
2. **Given** запрет поставлен, пока форма открыта, **When** пользователь отправляет запись,
   **Then** бот отвечает `BOOKING_BLOCKED`, 1С не вызывается, форма показывает то же сообщение.
3. **Given** у пользователя под запретом есть активная запись, **Then** он видит её и может
   отменить или перенести.
4. **Given** запрет снят, **Then** пользователь снова записывается как обычно.

### User Story 2 - Администратор видит запреты (Priority: P2)

Под таблицей записей — список запретов: ID (ссылка на поиск его записей), причина, число записей в
боте, когда и кем поставлен, кнопка «Снять запрет». В таблице записей у такого пользователя метка
«запрет записи».

## Requirements *(mandatory)*

- **FR-001**: Запрет хранится в таблице `booking_bans` (схема БД v5): ID пользователя, причина до
  200 символов, время, логин администратора. ФИО и телефон не хранятся.
- **FR-002**: `POST /book` для пользователя под запретом отвечает
  `{"status":"error","error":"BOOKING_BLOCKED","message":…}` без обращения к 1С.
- **FR-003**: `GET /my_appointment` возвращает `booking_blocked: true|false`.
- **FR-004**: Перенос и отмена существующей записи не запрещаются.
- **FR-005**: API админки: `GET /admin/api/bans`, `POST /admin/api/bans {user_id, reason}`,
  `DELETE /admin/api/bans/{user_id}`; изменения — с заголовком `X-Admin-Request`, в журнал пишется
  только ID.
- **FR-006**: Запрет действует, пока его не снимет администратор.

## Out of scope

- Автоматический запрет по числу неявок (нужен надёжный признак неявки из 1С).
- Запрет записи через колл-центр — решение регистратуры.
