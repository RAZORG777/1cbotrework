# Research: Новый WebApp записи

## R1. Одна форма, две сборки

- **Decision**: исходники в `webapp/`, режимы Vite `telegram` и `max`. Режим задаёт `base`
  (`/` или `/max/`), каталог вывода (`../telegram_bot/static/app`, `../max_bot/static/app`),
  тег SDK в `index.html` и выбор адаптера платформы (`import.meta.env.MODE`, мёртвая ветка
  вырезается сборщиком).
- **Rationale**: единые макеты и поведение; раздельные артефакты на каждый бот.
- **Alternatives**: копия формы в каждом боте (расхождение), одна сборка с определением
  платформы во время работы (оба SDK в каждом бандле, лишний вес и путаница с базой API).

## R2. Выдача сборки ботом

- **Decision**: `GET /` (MAX — `/max/`) отдаёт `static/app/index.html` с `Cache-Control:
  no-cache`; ассеты с хэшем в имени — `StaticFiles` на `/assets` (MAX — `/max/assets`),
  `check_dir=False`, чтобы бот стартовал и без сборки; без сборки `GET /` отвечает 503 с
  текстом «Форма не собрана». Логотип и шрифт — внутри сборки; маршрут `/Логотип.png` удаляется.
- **Rationale**: хэшированные имена позволяют долго кэшировать ассеты и сразу выдавать новую
  версию после выкладки; явная ошибка лучше старой формы в тени.

## R3. Адаптер платформы

- **Decision**: интерфейс `Platform` (initData, схема цвета и подписка на смену, главная кнопка,
  «Назад», вибрация, хранилище, закрытие, открытие ссылок, флаги нативности).
  - Telegram: `MainButton` (setParams с цветом бренда, showProgress), `BackButton`,
    `colorScheme` + событие `themeChanged`, `setHeaderColor`/`setBackgroundColor`/`setBottomBarColor`
    в токенах темы, `disableVerticalSwipes` (где есть), `CloudStorage`, `HapticFeedback`, `ready`, `expand`.
  - MAX (документация bridge): есть `BackButton` (show/hide/onClick/offClick), `HapticFeedback`
    (impactOccurred, notificationOccurred, selectionChanged), `DeviceStorage` (только мобильные),
    `openLink`; `MainButton` и тема не документированы → своя закреплённая кнопка и
    `prefers-color-scheme`. Всё — через проверку наличия.
- **Rationale**: экранам безразличен канал; тесты подменяют платформу заглушкой.

## R4. Навигация без роутера

- **Decision**: стек экранов в состоянии (`home → choose → doctorServices|serviceDoctors → time →
  patient → success`, `my`), «Назад» снимает верхний экран; направление перехода задаёт
  анимацию. Адрес не меняется (мини-приложение открывается всегда с начала).
- **Alternatives**: vue-router — лишний вес, история браузера конфликтует с BackButton мессенджера.

## R5. Анимации

- **Decision**: CSS-переходы Vue `<Transition>` и ключевые кадры в `main.css`: вход шага
  260 мс сдвиг 24 px + прозрачность, `cubic-bezier(0.22,1,0.36,1)`; нажатие `scale(.97)` 100 мс;
  скелетон — отблеск 1,4 с; моргающий глаз 2,6 с; три точки 1 с; «Вы записаны» — круг 460 мс,
  галочка 360 мс с задержкой 200 мс, подъём блоков со сдвигом 60 мс; «время заняли» — баннер
  сверху 300 мс, кольцо у слота 700 мс один раз. `@media (prefers-reduced-motion: reduce)` —
  проявление 150 мс, бесконечные анимации выключены. Без библиотеки анимаций.
- **Rationale**: совпадает с досками «Анимации», не требует зависимостей, укладывается в бюджет веса.

## R6. Шрифт и иконки

- **Decision**: `@fontsource-variable/onest` (кириллица + латиница, woff2 в сборке),
  `@phosphor-icons/vue` с импортом только используемых иконок, толщина `regular`.
- **Alternatives**: Google Fonts (запрещено: CDN), свои SVG (запрещено правилами дизайна —
  самодельные иконки).

## R7. Перенос без повторного ввода данных

- **Decision**: `POST /reschedule` принимает `patient` необязательным. Нет `patient` — бот берёт
  ФИО, телефон и дату рождения из своей активной записи (они сохранены при записи), согласие не
  требуется (новые ПДн не принимаются). Есть `patient` — как раньше, с обязательным согласием.
- **Rationale**: SC-003 (перенос за 3 нажатия); ПДн не гоняются через форму лишний раз.

## R8. Данные «Моей записи»

- **Decision**: `/my_appointment` добавляет `doctor_id`, `service_id`, `confirmed` (bool по
  `confirmed_at`). ПДн пациента не добавляются: имя пациента форма показывает из сохранённого
  на устройстве профиля, если он есть, иначе строка скрыта.

## R9. Тесты формы

- **Decision**: Playwright на `vite preview` каждой сборки; `addInitScript` ставит заглушку
  `window.Telegram.WebApp` / `window.WebApp` с `initData`, запросы к SDK и к API перехватываются
  `page.route` фикстурами; снимки 320/390/430 × светлая/тёмная для ручной проверки, проверки
  «нет горизонтальной прокрутки» и «кнопки ≥ 44 px» — утверждениями.
- **Rationale**: проверяется настоящая сборка, без доступа к 1С и мессенджерам.

## R10. Node на сервере выкладки

- **Decision**: `deploy.ps1` выполняет `npm ci` и `npm run build` в `webapp/`, если найден
  `npm`; иначе останавливается с сообщением «Установите Node.js 22 LTS». Сборка в git не хранится
  (конституция: сборки в `.gitignore`).
- **Open**: наличие Node.js на боевом сервере проверить перед выкладкой этапов 0–3 на прод.
