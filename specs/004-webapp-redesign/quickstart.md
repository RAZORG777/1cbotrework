# Quickstart: проверка нового WebApp

## Сборка и тесты формы

```bash
cd webapp
npm ci
npm run typecheck && npm test          # Vitest
npm run build                          # обе сборки → ../telegram_bot/static/app, ../max_bot/static/app
npm run e2e                            # Playwright: сценарии и снимки 320/390/430, светлая/тёмная
```

Ожидание: всё зелёное, в `webapp/e2e/screenshots/` снимки экранов.

## Боты

```bash
cd telegram_bot && pytest -q && ruff check . && ruff format --check .
cd ../max_bot   && pytest -q && ruff check . && ruff format --check .
```

## Тестовый контур (Telegram)

1. Собрать форму (`npm run build` в `webapp`), перезапустить тестового бота.
2. Открыть форму из тестового бота на телефоне. Светлая тема: шаг 1 из 4, два филиала.
3. Записаться: филиал → «Врачи» → врач → услуга → дата/время → пациент → «Записаться».
   Ожидание: «Вы записаны», сообщение в чате, заявка в тестовой УМЦ.
4. Закрыть и открыть форму: сразу «Моя запись».
5. «Перенести на другое время» → другое время → «Перенести на …». Ожидание: заявка в УМЦ
   перенесена, данные пациента не спрашивались.
6. «Отменить запись» → «Да, отменить». Ожидание: «Запись отменена», заявка отменена в УМЦ.
7. Переключить тему Telegram на тёмную при открытой форме: палитра меняется сразу.
8. Время заняли: выбрать время, занять его в УМЦ, нажать «Записаться» → баннер, слот перечёркнут.
9. Путь «Услуги»: услуга → врач из тех, кто её оказывает → время.
